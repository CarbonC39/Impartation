## 待讨论的产品决策

1. 登录方式：第三方登录、邮箱密码或邮箱链接？第三方方式需要对应应用配置；邮箱验证、找回密码或邮箱链接需要邮件发送能力。
2. 是否允许未登录访客入房、聊天和发布留言？是否允许公开注册，或只邀请少数朋友？
3. 旧访客留言如何处理？建议保留旧权限规则，不按同名昵称认领。若支持登录时认领，应仅认领服务端确认属于当前访客会话的留言。
4. 第一版是否需要改密码、找回密码、注销账号？邮箱密码面向真实用户使用时应明确找回路径；第三方方式可先依靠提供方的账号恢复。

## 认证库初步评估

2026-10-10 查阅官方文档与 npm 元数据，尚未安装或做兼容性验证。

| 方案 | 与当前仓库的关系 | 成本与待验证项 |
| --- | --- | --- |
| Better Auth（优先候选） | 官方提供 Express、better-sqlite3 和数据库会话支持；适合把账号与游戏房间分开 | npm 当前版本 1.7.7，MIT；主包解压约 1.98 MiB，不含依赖，不代表浏览器体积。需要认证表迁移、配置密钥、Cookie/origin 与房间会话桥接；邮件或 OAuth 配置取决于登录方式 |
| `@colyseus/auth`（备选） | 与 Colyseus SDK 的认证接口直接关联 | npm 当前版本 0.18.4，MIT；主包解压约 315 KiB，不含依赖。官方仍标 beta；当前 SQLite 使用方式下需要接入用户存储回调或评估 `@colyseus/database` 的额外迁移成本 |

推荐以 Better Auth 做兼容性验证；该建议未构成最终选型。账号、会话和密码管理交由库提供，不手写认证协议或密码算法。当前单实例 SQLite 可继续评估复用；实际依赖增量、构建产物体积和版本兼容性在接入时测量。

资料来源：[Better Auth Express](https://better-auth.com/docs/integrations/express)、[SQLite](https://better-auth.com/docs/adapters/sqlite)、[会话管理](https://better-auth.com/docs/concepts/session-management)、[Colyseus Auth](https://docs.colyseus.io/auth/module)、[房间认证](https://docs.colyseus.io/auth/room)。包版本、许可和主包解压尺寸来自 `npm view better-auth` 与 `npm view @colyseus/auth`。

## 实现时需要守住的边界

认证会话与 Colyseus 的房间 `sessionId` 是两种不同身份：同一个账号可有多条房间连接，留言所有权绑定账号。邮箱、密码、认证 Cookie 和第三方令牌不能进入公开 Schema。客户端提交的 `userId`、昵称或留言作者不能作为授权依据。

当前 `onAuth` 只校验访客昵称/头像，退出、会话撤销和网络重连都还没有账号语义。接入时必须定义：退出或会话失效后，已有 WebSocket 如何停止以账号身份执行操作；重连如何重新校验会话。不能只在首次入房时验证一次。

默认优先评估前后端同源部署和由认证库管理的 HttpOnly Cookie；当前 Vite 代理尚无认证路由，需要随接入增加并验证。跨域部署需单独确定 Cookie、允许的 origin 和 SDK 凭据传递方式；本轮尚未验证。

业务资料与留言所有权迁移使用版本化数据库迁移；认证库的表使用其支持的迁移机制，并验证与项目现有 `user_version` 迁移不冲突。原有留言不依据昵称转换为账号所有权。
